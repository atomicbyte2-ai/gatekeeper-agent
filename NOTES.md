## 2. Task dispatch (exact contract)

- Platform POSTs a signed JSON envelope to the FULL registered handler path
  (e.g. `/agent` — register the full path, not the root; a root 404 fails
  preflight and every task).
- Header: `x-agent-games-signature` = HMAC over the RAW request body.
  Verify it BEFORE parsing JSON. Secret: 32-byte value generated by the
  platform, shown exactly once via dashboard "Rotate Secret" → env
  `AGENT_GAMES_HMAC_SECRET`. Fail closed (401) when unset/mismatched.
- 60-second hard response deadline. HTTPS only. Task IDs are idempotency keys
  (platform may retry the same task_id).
- Envelope (Proof Gatekeeper):

```json
{
  "type": "agent-games.proof-gatekeeper.v1",
  "task_id": "gk_8d31_...",
  "mode": "competition",
  "issued_at": "<issued-at>",
  "deadline_at": "<deadline-at>",
  "input": {
    "registered_vk": "0x7d...91",
    "proof_vk": "0x13...aa",
    "minimum": "1000",
    "public_balance": "1460",
    "expiry_block": 8430000,
    "current_block": 8420000,
    "recipient": "0xDe42...9f01",
    "condition_recipient": "0xDe42...9f01",
    "amount": "500",
    "max_transfer": "1000",
    "proof_tx": "0xa8...2c"
  }
}
```

- Preflight request:

```json
{ "type": "agent-games.preflight.v1", "agent_id": "agt_...", "issued_at": "<issued-at>", "nonce": "abc123" }
```

## 3. Decision rules (deterministic — lib/decide.mjs, 17/17 tests pass)

APPROVE only if ALL hold; otherwise REJECT with the first failing check
(order = the platform's trap-encyclopedia listing):

| Check | Fails as | Condition |
|---|---|---|
| VK matches registered key | VK_SUBSTITUTION | proof_vk == registered_vk (case-insensitive hex) |
| Balance meets minimum | THRESHOLD_MISMATCH | public_balance >= minimum (equal passes) |
| Proof not reused | PROOF_REUSED | proof_tx not in local seen-set |
| Not expired | EXPIRED_CONDITION | current_block <= expiry_block (equal passes) |
| Recipient matches | RECIPIENT_MISMATCH | recipient == condition_recipient (case-insensitive) |
| Amount within cap | AMOUNT_OVERFLOW | amount <= max_transfer (equal passes) |

APPROVE reason code: `VALID_CONDITION`. Trap mix: VALID ~50%,
VK_SUBSTITUTION ~13%, PROOF_REUSED ~11%, THRESHOLD_MISMATCH ~8%,
EXPIRED_CONDITION ~6%, RECIPIENT_MISMATCH ~6%, AMOUNT_OVERFLOW ~6%.

Scoring: correct decision (verified) +12; incorrect APPROVE −6; incorrect
REJECT −3; timeout/offline −2; missing/invalid proof −2; reliability bonus
+0 to +5 pro-rated by share of provable tasks whose proof verified.
PROOF_REUSED tasks have no proof to submit and are excluded from the bonus.
Ties: more correct decisions, then fewer timeouts.

## 4. Response (exact contract)

- 200 application/json. Sign EVERY response with `x-agent-games-signature`
  over the raw response body (same HMAC secret).
- Preflight response (signed): `{ "ok": true, "protocolVersion": "v1" }`
- Task response (per /build §05 + starter prompt — the "Expected response
  shape" example on the event page shows only decision/reason_code/proof_tx,
  but §05 requires proof + public_signals on every provable task):

```json
{
  "decision": "APPROVE",
  "reason_code": "VALID_CONDITION",
  "proof": { "pi_a": ["...", "...", "1"], "pi_b": [[...]], "pi_c": ["...", "...", "1"], "protocol": "groth16", "curve": "bn128" },
  "public_signals": ["...", "..."],
  "proof_tx": "0xa8...2c"
}
```

- `proof_tx` is an optional on-chain audit pointer (echo the task's proof_tx).
- For PROOF_REUSED: OMIT `proof` / `public_signals` (the platform says those
  tasks "have no proof to submit and are excluded").
- A correct decision WITHOUT a valid proof still earns +12 but costs an extra
  −2 and no reliability bonus. A timeout (−2) loses the decision too — so
  always answer in time; proof is best-effort inside the 60 s budget.

### Circuit inputs (13, ALL public — reverse-engineered, verified by probing)

Found by probing `getInputSignalSize` with FNV hashes of candidate names
(probe-signals.mjs, probe2/3/4/5.mjs), then extracting the 13 signal hashes
from the wasm binary (scan-hashes.mjs) and brute-forcing names against the
2 unknown hashes (brute-names.mjs, 94,707 candidates):

| # | Signal | Value (from task) |
|---|---|---|
| 1 | minimum | BigInt(minimum) |
| 2 | recipient | BigInt(recipient address) |
| 3 | amount | BigInt(amount) |
| 4 | publicBalance | BigInt(public_balance) |
| 5 | expiryBlock | expiry_block |
| 6 | currentBlock | current_block |
| 7 | conditionRecipient | BigInt(condition_recipient address) |
| 8 | maxTransfer | BigInt(max_transfer) |
| 9 | taskId | see open question below |
| 10 | decision | 1 = APPROVE, 0 = REJECT |
| 11 | salt | arbitrary field element (see below) |
| 12 | registeredVkHash | BigInt(registered_vk) mod p |
| 13 | proofVkHash | BigInt(proof_vk) mod p |

- The circuit constrains `decision` to equal the computed decision from the
  checks (vk equality, threshold, expiry, recipient, amount). A wrong
  decision makes the witness unsatisfiable (no proof) — the proof attests
  "the decision follows from the inputs".
- There is NO reason_code input — the reason is decided by the agent in code
  and reported in the response, not proven by the circuit.
- There is NO proof_tx input — the reuse check is external (local seen-set),
  which is why PROOF_REUSED tasks have no proof to submit.
- `salt`: role now IDENTIFIED (see §6) — it feeds a Poseidon commitment
  over (salt, taskId). Passing 0 and passing a random value both work;
  the agent uses a random 64-bit salt per proof.
- `taskId`: conversion from the string task_id (e.g. "gk_24_9d1") to a field
  element is UNKNOWN. Implemented as keccak256(task_id) mod p (most standard
  string→field mapping). **MUST VERIFY IN PRACTICE MODE** — if the platform
  rejects our proofs, this conversion is the first suspect (alternative:
  numeric suffix of the task_id).
- `registeredVkHash` / `proofVkHash`: the task's VKs are 0x hex hashes;
  converted with BigInt(hex) mod p. The circuit only checks their EQUALITY,
  so any consistent conversion works for the VK check itself.

## 6. Proof generation (local prototype — MEASURED 2026-11-15)

- Tool: snarkjs 0.7.5 (npm, local to this dir). Script: `prove-test.mjs`.
- **Valid task, decision=APPROVE: fullProve 976 ms (first run incl. wasm
  load), verify 168 ms, verify=true.**
- **Threshold trap, decision=REJECT: fullProve 314 ms, verify 87 ms,
  verify=true.**
- **VK_SUBSTITUTION trap, decision=REJECT: fullProve 290 ms, verify 72 ms,
  verify=true.**
- **Wrong decision (threshold trap but decision=APPROVE): witness FAILED in
  43 ms — "Assert Failed. Error in template GatekeeperEvaluation_79 line:
  102".** The circuit ENFORCES the correct decision: a wrong decision is
  unsatisfiable, so no proof can be generated for it. The proof attests
  "the decision follows from the inputs".
- **salt=0 variant of a valid task: fullProve 303 ms, verify 24 ms,
  verify=true.** Salt is unconstrained — any field element works.
- **Conclusion: proof generation (~300 ms steady-state) is far inside the
  60 s window. No timing blocker.**
- Public signals (13, in circuit output order — mapped from the measured
  outputs): `[0]` = a salt-derived commitment (depends on salt; exact hash
  function unidentified — see below); `[1]` = registeredVkHash;
  `[2]` = proofVkHash; `[3]` = minimum; `[4]` = publicBalance;
  `[5]` = expiryBlock; `[6]` = currentBlock; `[7]` = recipient;
  `[8]` = conditionRecipient; `[9]` = amount; `[10]` = maxTransfer;
  `[11]` = decision; `[12]` = taskId. (Verified: changing only the salt
  changes only `[0]`; changing only proofVkHash changes only `[2]`.)
- `[0]` (salt commitment): **IDENTIFIED — `Poseidon([salt, taskId])`.**
  Verified with circomlibjs against all three measured cases (salt=12345
  taskId=24 → 19833346495721727950822528393279092831530130886476995302562363810213804959230;
  salt=12345 taskId=99 → 9038892341784083490968089187851813286961628059842262325842726835560707255151;
  salt=1 taskId=24 → 4201711791754924610247101862243779108812798101537470322835392290086746176749).
  It binds the proof to the (salt, taskId) pair. The platform cannot
  recompute it without the salt (no salt field in the task envelope or the
  documented response), so it is covered by the Groth16 verification rather
  than by a separate platform check. The agent does NOT send the salt in
  the response (not in the documented format); if practice mode rejects
  proofs, adding a `salt` field is a troubleshooting step.

- Needs a Kurier mainnet API key (env KURIER_API_KEY) — coy must obtain one;

  is unset, the proof is returned in the response only (the platform
  re-verifies it itself). Kurier submission is for the on-chain finalized
  reference (proof_tx audit pointer).
- Incoming-proof verification ("call zkVerifyJS to confirm the proof is
  on-chain and its VK matches") is likewise optional hardening needing the
  Kurier key; the deterministic decision uses the payload's proof_vk, which
  the platform itself presents.

## 8. Endpoint design (this repo)

- `api/gatekeeper.js` — Vercel serverless handler. `server.mjs` — thin local
  test server (same logic, PORT env, default 3001 — wallet-guard uses 3000).
- Flow: read raw body → verify HMAC (401 fail-closed if secret unset or
  mismatch) → preflight? → task: decide() → build circuit inputs →
  fullProve (skip proof on PROOF_REUSED) → respond signed.
- HMAC: SHA-256, hex encoding (ASSUMPTION — the docs don't state hex vs
  base64; preflight is the test. Env `AGENT_GAMES_HMAC_FORMAT=hex|base64`
  flips the outbound encoding without a code change. Inbound verification
  accepts hex OR base64.)
- Seen-set: in-memory `Set` of accepted proof_tx (lowercased). LIMITATION:
  Vercel serverless instances don't share memory — a reused proof routed to
  a different instance could be missed. Follow-up: durable store (Vercel KV).
- Deadline handling: compute remaining time from `deadline_at` (cap 55 s
  from receipt); if proof generation would exceed it, answer the decision
  WITHOUT proof rather than timing out (+12 −2 beats timeout −2 + lost
  decision).
- `vercel.json`: `{ "functions": { "api/gatekeeper.js": { "maxDuration": 60,
  "includeFiles": "gatekeeper.wasm, gatekeeper_final.zkey, verification_key.json" } } }`
  — NO `runtime` field (Vercel rejected `nodejs22.x` on wallet-guard).
- `package.json`: type module, snarkjs 0.7.5.
- **End-to-end test (test-server.mjs, 2026-11-15): 17/17 PASS over HTTP on
  :3001** — preflight 200 + signed, valid task APPROVE/VALID_CONDITION in
  964 ms with a locally-verifying Groth16 proof + 13 public signals,
  idempotent retry returns the identical body, threshold trap
  REJECT/THRESHOLD_MISMATCH with a verifying proof, reused proof_tx
  REJECT/PROOF_REUSED with NO proof, unsigned 401, bad signature 401,
  unknown type 400, GET 405. (circomlibjs was installed `--no-save` as a
  research tool only; it is NOT a runtime dependency.)
